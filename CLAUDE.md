# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

This repository contains the code to replicate the analysis in the manuscript *Somatic and germline mutational processes across the Tree of Life*. It is a collection of standalone analysis scripts, not an installable library or application. There is no test suite and no build step.

The scripts run after variant calling. Germline mutations come from [deepvariant](https://github.com/google/deepvariant) and somatic mutations come from [himut](https://github.com/sjin09/himut) (PacBio CCS reads). Those tools live in other repositories.

## Environment

```
conda env create --file environment.yml
conda activate treeoflife
poetry install
```

- Python is pinned to 3.9 (`>=3.9,<3.10` in `pyproject.toml`).
- Black line length is 120. flake8, black and pytest are listed as dev extras.
- R scripts need the `hdp` package for signature extraction, plus `ggtree`, `ape`, `ggplot2` and similar packages for plotting. R dependencies are not managed by any lockfile.

## Analysis pipeline

The usage docs in `docs/*.md` (linked from `README.md`) give exact command lines. The data flow is:

1. **Trinucleotide counts**: `get_reference_tricounts.py` counts the 3-mers in a reference FASTA, collapsed so the middle base is a pyrimidine (`.tri` file).
2. **Spectra**: `get_sbs96_counts.py` (somatic VCF) and `get_sbs52_counts.py` (germline VCF) write count TSVs. `get_sbs96_barplot.py` and `get_sbs52_barplot.py` plot them.
3. **Normalisation**: `get_tri_equal_weight_sbs{96,52}_counts.py` reweights the counts using the `.tri` file so that each trinucleotide contributes equally.
4. **SBS96 → SBS52 mapping**: `get_sbs96_mapped_to_sbs52.py` maps the counts using `scripts/sbs96_to_sbs52_lookup_table.tsv`, which is generated by `get_sbs96_to_sbs52_lookup_table.py`. Mapping somatic spectra into the germline SBS52 space makes the two comparable. `docs/sbs96_to_sbs52.md` refers to a script called `sbs96_to_sbs52.py`, but the actual script is `get_sbs96_mapped_to_sbs52.py`.
5. **HDP matrices**: `write_somatic_mutation_hdp_matrix.py` and `write_germline_mutation_hdp_matrix.py` write a samples × channels TSV.
6. **Signature extraction (R, in `code/`)**:
   - Run `hdp_noprior_SBS{96,52}.R <matrix> <chain_index> <prefix>` 10 times, with chain index 1 to 10. Each run writes `<prefix><i>.rds`.
   - Then run `hdp_extraction_SBS{96,52}.R <prefix> <matrix> <outdir> <outprefix>`. It combines the 10 chains and writes `<outprefix>_HDP_sigs.csv` and `<outprefix>_HDP_exposure.csv`.
   - Both steps drop samples with fewer than 100 mutations.
   - These are the "farm" (cluster) versions. Keep the chain count and file naming consistent between the two scripts.
7. **Phylogenetic signal**: `get_abouheif_C_mean.py` builds a tree from the taxonomic classification and computes Abouheif's Cmean for each signature. Pass `--is-somatic` for somatic signatures.
8. **Figures**: the `plot_*.R` and `plot_*.py` scripts produce the manuscript figures, including the main figures 3–5, extended data figures, supplementary figures and the circular trees in `plot_all_sample_taxonomic_tree.R` and `tree_with_heatmap.R`.

## Naming conventions

- **SBS96** is the somatic classification: 6 substitution types × 16 flanking contexts, with channels written like `A[C>A]A`. **SBS52** is the germline classification.
- **sToL** and **gToL** are the somatic and germline Tree of Life signatures. "rtol" and "x0_excluded" in filenames refer to filtered attribution sets.
- `tri_equal_weight` means trinucleotide-normalised counts.

## Script conventions

- Python scripts follow a single template: a `parse_args(args)` function that uses argparse and strips `args[0]`, a `main()` function, and `sys.exit(main())`. Run them as `python scripts/<name>.py ...`. New scripts should follow the same pattern.
- R figure scripts read their inputs through relative paths such as `../data/dtol/...`, so run them from `scripts/`. Several of them (`plot_extended_data_figure_3.R`, the `plot_supplementary_figure_*.R` scripts and `plot_extended_data_figure_8.R`) contain hardcoded or commented-out `setwd()` calls pointing to author-local paths. Check these before running.
- In the manuscript figure scripts, all plot text is Helvetica at 5–7 pt.

## Data layout

- `data/dtol/`: Darwin Tree of Life sample sheets, taxonomic classifications, Newick trees, COSMIC v3.4 reference signatures, the final germline and somatic signature attributions, and the Cmean results.
- `data/gold_standard/`, `data/positive_control_samples/`, `data/negative_control_sample/`: human control samples (hg19) used for validation.
- `pluto/`: an exported Pluto (Julia) notebook (`DToL_signatures.html`) and the HDP outputs it uses.
- `figures/`: one README placeholder per figure. These are currently empty.
